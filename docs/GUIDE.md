# من الصفر إلى أول إصلاح

دليل لمن بنى برنامجه مع مساعد ذكي ولا يعرف تفاصيل البرمجة. انسخ كل أمر كما هو، والصقه في الطرفية
(Terminal)، واضغط Enter. كل أمر ينتهي بمربع يقول لك ما حدث، وما الأمر التالي.

> **الأسهل:** إن كنت تستعمل Claude Code أو Codex، نفّذ الخطوة ١ ثم الخطوة ٢، وبعدها كلّم مساعدك بكلامك:
> «افحص مشروعي»، «وش المشاكل؟»، «أصلح»، «وين وصلنا؟». هو يشغّل الأوامر ويشرح لك.

---

## ١. ثبّت EAOS (مرة واحدة)

```bash
curl -fsSL https://raw.githubusercontent.com/eom1417/engineering-audit-os/main/install.sh | bash
```

- **المدة:** من 3 إلى 10 دقائق.
- **المتوقع:** ✅ «تم تثبيت EAOS».
- **إن قال «افتح نافذة طرفية جديدة»:** أغلق الطرفية وافتحها من جديد.
- **يحتاج:** Python 3.10 أو أحدث، وgit. إن نقص أحدهما، يقول لك الأمر من أين تثبّته.

## ٢. علّم مساعدك الذكي (اختياري، ومرة واحدة)

```bash
eaos assistant install
```

- **المتوقع:** ✅ «صار مساعدك يعرف EAOS: Claude Code, Codex».
- بعدها افتح مساعدك في مجلد مشروعك، واطلب بكلامك.

## ٣. افحص مشروعك

افتح مجلد مشروعك في الطرفية، ثم:

```bash
eaos start .
```

- **المدة:** من 5 إلى 30 دقيقة، حسب حجم المشروع. ترى الخطوات أثناء العمل: `[3/26] أشغّل أدوات الفحص…`.
- **لا يتغير شيء في مشروعك.** كل ما يكتبه EAOS في مجلد منفصل: `~/.eaos/projects/`.
- **المتوقع:** ✅ «فحصت مشروعك: 584 مشكلة، منها 312 يمكن إصلاحها آليًا» (الأرقام حسب مشروعك).

لقراءة النتيجة بكلام بسيط:

```bash
eaos show
```

## ٤. جهّز الإصلاح

```bash
eaos next
```

يسألك سؤالًا واحدًا: هل يشغّل برنامجك في نسخة منفصلة على جهازك، بقاعدة بيانات مؤقتة وبلا أسرارك؟

- إن وافقت، اكتب ما يقوله المربع: `eaos next --yes`
- **المدة:** من 5 إلى 20 دقيقة. قد يستعين بمساعدك الذكي ليفهم طريقة تشغيل برنامجك.
- **المتوقع:** ✅ «برنامجك يعمل في النسخة المنفصلة».

## ٥. صوّر برنامجك قبل أي تغيير

```bash
eaos next
```

- **المدة:** من 15 إلى 30 دقيقة.
- يصوّر كل شاشة من شاشات برنامجك، ويقيس سرعته. بعد كل إصلاح، تُقارن الشاشات بهذه الصور: إن تغيّر شيء، يُرفض الإصلاح.
- **المتوقع:** ✅ «صوّرت 28 من 28 شاشة، وأبطأ الطلبات تأخذ 28 ملي ثانية».

## ٦. أصلح أول دفعة

```bash
eaos next
```

يسألك مرة واحدة: هل يصلح دفعات من الإصلاحات الجاهزة، ويضع ما ينجح في فرع جديد في مشروعك؟ إن وافقت:
`eaos next --yes`

- **المدة:** من 20 إلى 60 دقيقة للدفعة (10 إصلاحات).
- كل إصلاح يُجرَّب في النسخة المنفصلة: فحوص مشروعك، والشاشات، والتأكد أن المشكلة اختفت. ما يفشل يُترك، وسببه مكتوب.
- **المتوقع:** ✅ «نجح 9 من 10 إصلاحًا، وهي الآن في الفرع eaos/wave-1 في مشروعك». فرعك الحالي وملفاتك كما هي.

## ٧. اعتمد، أو تراجع

```bash
eaos accept    # لاعتماد الإصلاحات في مشروعك
eaos undo      # للتخلي عنها
```

ثم `eaos next` للدفعة التالية.

## أوامر مفيدة في أي وقت

| الأمر | ماذا يفعل |
| --- | --- |
| `eaos status` | أين وصلنا، وما التالي |
| `eaos show` | نتيجة الفحص بكلام بسيط |
| `eaos do "اطلب بكلامك"` | يفهم طلبك وينفّذه، مثل: `eaos do "وش المشاكل"` |
| `eaos doctor` | هل جهازك جاهز؟ وما الناقص وكيف تصلحه |
| `eaos clean` | يحذف النسخ المؤقتة ليوفّر مساحة |

## إذا ظهر لك…

| الرسالة | ماذا تفعل |
| --- | --- |
| «لم نبدأ مع هذا المشروع بعد» | افتح مجلد مشروعك، واكتب `eaos start .` |
| «مشروعك غير محفوظ في git بعد» | `git init && git add -A && git commit -m "first save"` ثم `eaos next` |
| «عندك تعديلات لم تُحفظ في git» | ليست مشكلة: EAOS يعمل على آخر نسخة محفوظة. لتدخل تعديلاتك: `git add -A && git commit -m "save"` |
| «المنفذ الذي يحتاجه مشغول» | أغلق خادم التطوير الذي يعمل في نافذة أخرى، ثم `eaos next` |
| «أداة فحص أحتاجها غير مثبّتة» | `eaos doctor --fix` |
| «Node.js غير مثبّت» | ثبّته من https://nodejs.org (نسخة LTS)، ثم `eaos next` |
| «مساحة القرص امتلأت» | `eaos clean` ثم `eaos next` |
| «أحتاج مساعدك الذكي» | ثبّت Claude Code أو Codex وسجّل الدخول، ثم `eaos next` |
| أي رسالة أخرى | اكتب `eaos next`. إن تكررت، أرسل ملف السجل المذكور في المربع لمن يساعدك |

## ما لا يفعله EAOS أبدًا

- لا يغيّر ملفات مشروعك ولا فرعك الحالي. الإصلاحات تصلك فرعًا منفصلًا، وأنت تقرر.
- لا يستعمل أسرارك ولا ملف `.env`، ولا يتصل بقاعدة بياناتك الحقيقية.
- لا ينشر شيئًا، ولا يلمس الإنتاج (Railway أو Vercel أو غيرهما).
