# خطة الدمج: من أداة واحدة إلى منسّق أدلة

> المبدأ: **نبني طبقات التنسيق والتطبيع والربط والاستدلال والحوكمة. ونستأجر كل محرك تحليل يتفوق على ما نستطيع إعادة بنائه بعقل.**

## 1. القرار المعماري الجوهري

لا نضيف المحركات كـ«ميزات». نضيف **نوعًا ثانيًا من منتجي الحقائق** تحت طبقة الحقائق، فتبقى كل الطبقات فوقها كما هي:

```
مستودع الهدف
   │
   ├─ eaos/facts/**      ← منتج حقائق داخلي (حتمي، Python عميق)
   └─ eaos/engines/**    ← منتجو حقائق خارجيون (enola, codegraph, reforge, jscpd)
              ↓
      eaos/facts/external.py   ← التطبيع إلى مخطط واحد
              ↓
      eaos/correlate.py        ← عنقدة عبر المحركات + تعاضد + تناقض
              ↓
      eaos/claims.py           ← ادعاء + ناقض + ثقة بحسب المصدر
              ↓
      eaos/probes.py           ← الحَكَم: من يحسم الخلاف
              ↓
      decisions → plan → compose → policy/delta
```

المكسب الحقيقي من هذا الترتيب: **كل ما بنيناه فوق الحقائق يعمل على أدلة المحركات بلا تعديل** — الفحوص، عقد القرار، بطاقات المهام، الموجات، عقد المخرجات، لوحة الاستدامة، بوابة الانحراف. هذا هو اختصار الطريق.

## 2. عقد المحوّل (§38)

كل محوّل يحقق نفس الواجهة، ولا شيء في القلب يعرف اسم أداة:

```python
name() -> str
version() -> str | None          # None = غير مثبَّت
health() -> (ok: bool, reason)   # اكتشاف قدرات حقيقي، لا افتراض
capabilities() -> [Capability]   # ما يخرجه فعلًا، بـ method: deterministic | heuristic
analyze(target, out, scope) -> Report
```

و`Report` موحّد: `{engine, version, status, findings[], coverage{}, provenance{}, raw_artifact}`.

كل نتيجة مطبَّعة تحمل: `engine, engine_version, rule, method, kind, subject{kind,key,path,line}, measurements[{name,value,threshold,unit}], message, raw_ref`.

## 3. التدهور الرشيق (§39) واكتشاف القدرات (§40)

- غياب محرك **لا يُفشل** الدورة؛ يُسجَّل في `coverage` كـ`status: unavailable` مع السبب، وتُخصم التغطية صراحةً في التقرير.
- الإصدار يُكتشف بالتشغيل (`--version`)، لا يُفترض. اختلاف `schema_version` عن المثبَّت ⇒ المحوّل يرفض ويُبلّغ، ولا يخمّن.
- كل تشغيل يكتب `run-manifest.json`: أي محرك، أي إصدار، أي بصمة، أي نطاق، وأي شيء لم يُشغَّل ولماذا.

## 4. نموذج الثقة بحسب المصدر (§31)

هذه أهم قاعدة في الدمج كله:

| الحالة | الثقة الابتدائية | هل تصل بطاقة مهمة؟ |
| --- | --- | --- |
| استخراج حتمي داخلي + فحص حاسم | CONFIRMED | نعم |
| محركان مستقلان بطريقتين مختلفتين يتفقان | LIKELY | بعد فحص |
| محرك واحد، قاعدة استدلالية | HYPOTHESIS | لا، تحقيق فقط |
| محرك يؤكد ومحرك بطريقة حاسمة ينفي | CONTESTED → HYPOTHESIS + `contested_by` | لا، فحص إلزامي |

الحالة الرابعة ليست افتراضية: دورة enola الوحيدة هي مثالها الحي.

## 5. علاج الضجيج (498 نتيجة خام)

1. **النطاق**: استثناءات التحليل المعلنة في `eaos.policy.json` تُمرَّر إلى كل محرك. jscpd بلا نطاق أبلغ 23.1٪ تكرارًا لأنه عدّ مخرجاتنا نفسها؛ مع النطاق: 1.85٪.
2. **العنقدة**: النتائج تُجمَّع حسب الموضوع (`subject.key`) إلى «عنقود مشكلة معمارية» واحد.
3. **العتبة**: نتيجة بلا `measurement` تتجاوز عتبتها لا تنتج ادعاءً.
4. **خط الأساس (§28)**: الموجود يُسجَّل ولا يُفشل؛ الجديد فقط يُبلَّغ. بدون هذا، أول PR يفشل بـ348 نتيجة قديمة.

## 6. كفاءة التوكنز (§34) — وهي مطلب صريح

- المحركات تعمل بـ Go/Rust محليًا: **~13 ثانية باردة، ~3 ثوانٍ دافئة** لكل التحليل. ولا سطر مصدر واحد يُرسل إلى نموذج.
- ما يصل إلى طبقة الاستدلال ليس الكود، بل: عناقيد مربوطة + قياسات + تغطية. حزمة نصية بمئات البايتات لا بملايينها.
- enola يكتب `llm_context.md` بحجم **2.5 كيلوبايت** لمستودع كامل، و jscpd يملك مُصدِّر `ai` موفّرًا للتوكنز — نستعملهما كحزم سياق جاهزة بدل توليدها.

## 7. الترتيب التنفيذي

| الموجة | العمل | الحالة |
| --- | --- | --- |
| E1 | سجل المنابع + التراخيص | ✅ `upstreams/registry.yaml` بإصدارات وبصمات وقيود مقيسة |
| E2 | عقد المحوّل + اكتشاف القدرات + تدهور رشيق | ✅ `eaos engines list`؛ محرك ينهار يُسجَّل `error` ولا يُسقط الدورة |
| E3 | أربعة محوّلات | ✅ الأربعة تعمل: 586 نتيجة مطبَّعة في ~11 ثانية |
| E4 | مجموعة حقائق `external` | ✅ `eaos facts --engines`، ومخرجها متطابق بايتًا عبر التشغيلات |
| E5 | محرك الربط | ✅ 586 نتيجة → 142 عنقودًا، بأحكام corroborated / single / contested |
| E6 | ادعاءات وفحوص للأدلة الخارجية | ✅ 50 ادعاءً (49 LIKELY + 1 HYPOTHESIS)، وسقف ثقة يمنع CONFIRMED |
| E7 | خط الأساس ومنع الدين الجديد | ⬜ لم يُنفَّذ بعد |
| E8 | ترقية المنبع كسير عمل | ⬜ لم يُنفَّذ بعد |

كل موجة منتهية انتهت بتشغيل فعلي، لا بهياكل فارغة (§51).

| القياس | القيمة |

| هل تغيّر المستودع الهدف أثناء التحليل | لا (مُثبَت ببصمة قبل/بعد) |

### ثلاثة قرارات هندسية فرضها الواقع

1. **enola يكتب داخل ما يقرأ.** يكسر ثبات «الهدف للقراءة فقط»، فصار يقرأ نسخة مرآة (روابط صلبة إن أمكن، وإلا نسخ)، ونتحقق ببصمة قبل/بعد أن الهدف لم يتغيّر.
2. **CodeGraph غير قابل للتكرار في كشف الاستيراد الميت**: تشغيلان باردان على شجرة لم تتغيّر أعادا 131 ثم 129 نتيجة. أُسقطت الأداة من مجموعة الحقائق وسُجِّل السبب في `declined_tools` بدل إضعاف ضمان التكرارية.
3. **الصمت ليس نفيًا إلا في الخصائص البنيوية.** عدّ صمت محرك عن قاعدة عتبة «تناقضًا» صنّف 184 حكمًا من 279 كمتنازع عليه. القاعدة الآن: الصمت ينفي في `cycle` وحدها، فصار المتنازع عليه حالة واحدة — وهي الحالة الحقيقية.
