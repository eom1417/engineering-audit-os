# EAOS داخل المساعد الذكي (MCP)

> الوضع: قرار المالك (2026-09-28): EAOS يُضاف إلى Claude Code أو Codex خادمَ MCP، والمساعد يدير العمل كله بأدواته.
> المهام في `docs/north-star.json`: NS9.T7 إلى NS9.T9، ثم NS9.T6 (الدليل والتجربة الكاملة). المؤشران X8 وX9.

## الفكرة

المستخدم يكتب لمساعده بكلامه: «افحص مشروعي وأصلح أهم المشاكل». المساعد يشغّل أدوات EAOS، ويقرأ الكود بنفسه، ويكتب
الإصلاحات، وEAOS يتحقق من كل إصلاح ويسلّمه فرعًا. يرجع المساعد إلى المستخدم مرتين فقط: موافقة واحدة قبل تشغيل البرنامج
وتعديل الكود، وقرار في النهاية (يعتمد الإصلاحات أو يتراجع عنها).

| المساعد (Claude أو Codex) | EAOS |
| --- | --- |
| يفهم الطلب ويقرر الخطوات | أدلة دقيقة: المشاكل وأماكنها، والبنية، والخطة |
| يقرأ الكود ويكتب الإصلاح | نسخة معزولة من المشروع، وقاعدة بيانات محلية |
| يقترح طريقة تشغيل البرنامج حين لا يكفي الاكتشاف | يرفض ما ليس آمنًا، ويشغّل، ويرجع النتيجة كما هي |
| يشرح للمستخدم بكلام بسيط | البوابات: المشكلة اختفت، لا شيء انكسر، الشاشات كما هي، لا ميزة حُذفت؛ ثم فرع مستقل |

EAOS لا يستدعي نموذجًا بنفسه في هذا الطريق: عقل العمل هو المساعد الذي يستخدمه المستخدم، بكل ما يرى من المشروع.
قواعد الأمان في EAOS لا في التعليمات: لا عنوان خارج هذا الجهاز، لا أمر خارج مدير الحزم وnode، لا لمس لفرع المستخدم.

## الأدوات

كل أداة تأخذ `project` (مجلد المشروع؛ الافتراضي المجلد الذي فُتح فيه المساعد). العمل الطويل مهمة (job) تُتابَع بـ`wait`.

| المجموعة | الأداة | ما تفعله |
| --- | --- | --- |
| الحال | `status` | أين وصل المشروع، والأداة التالية المقترحة |
| التشخيص | `audit` | الفحص الكامل (26 مرحلة) مهمةً؛ يُستأنف إن انقطع، ولا يعاد لنفس النسخة |
| | `wait` | ينتظر مهمة حتى دقيقة، ويرجع تقدمها أو نتيجتها |
| | `overview` | صحة المشروع: الأعداد، وأهم المشاكل، والخطة، وما لم يكتمل |
| | `findings` | المشاكل بتصفية (الخطورة، النوع، الملف، نص) |
| | `finding` | مشكلة واحدة كاملة: الدليل، ومقتطف الكود، والتحقق، والإصلاح المقترح |
| | `structure` | البنية: الطبقات، والمخالفات، والحلقات، والبنية المستهدفة |
| | `plan` و`card` | خطة الإصلاح بمراحلها، وبطاقة واحدة كاملة |
| | `report_file` | أي ملف من التقرير |
| التشغيل | `run_setup` | بعد موافقة المستخدم: يكتشف طريقة التشغيل ويجرّبها في نسخة معزولة |
| | `run_try` | يجرّب اقتراح المساعد (بيئة، أوامر، سكربت بيانات) بعد فحص الأمان |
| | `safety_net` | يصوّر الشاشات ويقيس السرعة قبل أي إصلاح |
| الإصلاح | `fix_start` | يفتح دفعة في نسخة معزولة، ويطبّق الإصلاحات الآلية (codemods)، ويرجع ما يحتاج المساعد |
| | `fix_read` | يقرأ ملفًا في النسخة المعزولة كما هو الآن |
| | `fix_edit` | يطبّق تعديل المساعد لبطاقة، ويفحصه فورًا؛ الفاشل يُرجع بسببه |
| | `fix_skip` | يترك بطاقة بسبب |
| | `fix_finish` | فحوص المشروع وقفل السلوك على الدفعة كلها، ثم فرع `eaos/wave-N` في المشروع |
| | `accept` و`undo` | يعتمد الفرع (بعد موافقة المستخدم) أو يحذفه |

وأوامر جاهزة (prompts) تظهر في Claude Code: `/mcp__eaos__audit` و`/mcp__eaos__fix` و`/mcp__eaos__status`.

## التثبيت

سطر `install.sh` نفسه، ثم يسجّل EAOS في Claude Code (`claude mcp add --scope user`) وفي Codex (`~/.codex/config.toml`)
تلقائيًا. لا ملف يكتبه المستخدم. الأوامر (`eaos start` وغيرها) تبقى طريقًا ثانيًا.
