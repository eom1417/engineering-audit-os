# Adoption record: the labelled precision set (NS38.T1)

Task: NS38.T1
Capability: measure the precision and recall of every EAOS detector on a hand-labelled set of real projects
plus seeded mutations, and hide the detectors under their declared bar.
Written: 2026-10-08, before any code of the task (rule "adopt before build", `docs/north-star.json → rules`).
Sources: `eaos-dev/planning/studio-v2/E-adopt-before-build.md` §6, §8, §17, §18 and the GitHub API on 2026-10-08
(licence, stars, last push, archive flag).

## What is needed

1. **Labels**: for four real projects (FleetManageWeb, finance-os, chief-ops, EAOS at its self-truth commit),
   items of the classes EAOS reports (duplication, overlap, multiple writers, data models, UI defects, dead and
   broken code, complexity, module state, access gaps, redundant work, cycles), each with `file:line` and a
   reason, written from the source before the report is read.
2. **Seeded mutations**: copies of the projects with known defects planted, so recall is measured on cases
   whose answer is certain.
3. **Scoring**: match each detector's output to the labels, then precision, recall and a declared bar per
   detector; the verdict (shown or hidden) is read by the product.

## Decision

**Build** the harness in EAOS (`tools/precision.py`), small and specific, because no candidate labels the classes
EAOS reports on TS/Python product code, and every candidate set is either another language, another class (security,
bugs) or snippets without a project around them. This matches `E-adopt-before-build.md` §18 ("Precision harness:
specific to EAOS's fact kinds and cards; no generic benchmark measures them").

**Reuse the methods**, not the data:

- From OWASP Benchmark: every class carries **negative** labels (look-alikes that are not defects), so a detector's
  false positives are counted, not guessed.
- From BigCloneEval: **seeded mutations** (inject a known copy, an unread module, a mutated global, a table
  without row-level security, a twin page) into a copy of the project, so recall is measured where the answer is
  certain.
- From ACT Rules: a rule's verdict is only trusted on its labelled examples; a detector under its bar is hidden,
  not shown with a caveat (`MASTER-PLAN.md` §7).

What EAOS builds (≈ 400 lines, no new dependency): the truth format (`eaos-dev/truth/<project>.json`, items with
`file:line` sites, a one-line reason, exhaustive scopes for precision), the seeding of mutations into copies, the
matcher from each detector's cards and facts to the sites, and the verdict file the product reads. Licences: nothing
is embedded or redistributed; no labelled third-party data is copied.

Revisit: ACT Rules when the screens lane (P5) ships a UI detector; BigCloneBench if a Java project enters the corpus.
