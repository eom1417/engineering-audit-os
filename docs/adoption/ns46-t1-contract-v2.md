# NS46.T1: contract v2 and its fixtures

Scouting record for the Studio's contract v2 (docs/STUDIO.md D7): the additive section schemas, the coverage section,
and the synthetic data folder of 5,000 cards and 1,000 components. Written 2026-10-08, with the code of the same task.
The candidates come from what EAOS already uses and from the usual open-source choices; their versions were not
re-checked online for this record, so none is pinned.

## Section schemas

**Candidates**

| Candidate | Licence | Checked | Maintenance | Fit |
|---|---|---|---|---|
| JSON Schema draft-07, generated by `tools/make_contracts.py` (already in EAOS) | n/a (spec) | 2026-10-08, in the repository | the format every contract of EAOS uses; `eaos/artifact_contracts.py` validates it with no dependency | the Studio's v1 contract is written this way |
| TypeSpec | MIT | not re-checked | active (Microsoft) | a second source language for the same shapes |
| Zod schemas in the Studio | MIT | not re-checked | active | validates in the browser only; EAOS writes the data in Python |

**Decision**

Adopt what exists: the v2 sections are written in `tools/make_contracts.py` beside v1, as draft-07 schemas with a
packaged copy, judged by `eaos/artifact_contracts.validate`. A second schema language would split the one source.

**Pinned**

none

## Synthetic data at scale

**Candidates**

| Candidate | Licence | Checked | Maintenance | Fit |
|---|---|---|---|---|
| hypothesis-jsonschema | MPL-2.0 | not re-checked | maintained with Hypothesis | random valid documents per schema; no links between sections |
| json-schema-faker | MIT | not re-checked | maintained | the same, in Node |
| Faker / Mimesis | MIT | not re-checked | active | realistic words and names, no schema |

**Decision**

Build, in `tools/studio_synthetic.py` (about 200 lines). The Studio needs one project whose sections point at each
other (a card's evidence, a function's callers, a gap's operations, an operation's step), deterministic for a seed so
a gate run can be repeated, and offline with no new dependency. Schema-driven generators produce valid but unlinked
documents, and a page tested on unlinked data proves nothing about its links. The output is checked against the same
contracts, by `tests/test_studio_contract_v2.py`.

**Pinned**

none
